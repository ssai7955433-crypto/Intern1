# Architecture

## Request flow

```text
HTTP POST /ask
  -> Pydantic request validation (required string, 1–1,000 chars, no extra keys)
  -> safety checks (empty, excessive length, common instruction override)
  -> BM25 retrieval over heading-bounded Markdown sections
  -> no evidence above threshold? -> insufficient_evidence, empty citations
  -> extractive evidence response (default)
       or local Ollama generation (opt-in)
  -> Pydantic response validation
  -> caller verifies source / heading / excerpt citations
```

## Data model

- **Policy section (`Chunk`):** source filename, Markdown heading, extracted section text.
- **Search result (`ScoredChunk`):** policy section plus BM25 relevance score.
- **Citation:** source filename, human-readable heading, stable `filename#heading-slug` identifier, and excerpt.
- **API response:** status (`supported`, `insufficient_evidence`, or `refused`), answer text, and citation array.

The static index is built at process startup from `data/policies/*.md`. The BM25 implementation uses tokenized term frequency, inverse document frequency, and length normalization. No embedding or external vector database is needed for this small corpus; a larger corpus would call for a measured comparison against a semantic or hybrid index.

## Generation and validation

The deterministic baseline returns the top passages with their IDs. Optional Ollama mode sends only the question and retrieved excerpts and requests JSON containing an answer and citation IDs. The implementation checks JSON shape, non-empty answer, and citation membership in the retrieved set. Invalid generation is a surfaced `502` response, not a silent fallback.

Citation membership is not proof that each sentence is entailed by its cited passage. Human review and entailment evaluation are required before any production use.

## Interfaces

- `GET /health`: process health.
- `GET /documents`: indexed source filenames.
- `POST /ask`: question request and structured answer.
- `GET /docs`: interactive OpenAPI documentation generated by FastAPI.

## Failure behavior

| Condition | Behavior |
|---|---|
| Invalid JSON/schema, missing or extra fields, wrong field type | FastAPI/Pydantic validation response |
| Empty or >1,000-character question | HTTP 400 from application validation / schema validation |
| Prompt override request | `refused`, no retrieval citations |
| No matching evidence above threshold | `insufficient_evidence`, no citations |
| Ollama unavailable, malformed, empty, or uncited result | Explicit HTTP 502 |
| No usable policy sections at startup | Startup exception with corpus path |
